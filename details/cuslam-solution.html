01 / CUSLAM

核心结论 这是有实质算法改动的内部派生仓库

仓库已经定位：fourier_infinityrepo/perceptionnav/cuvslam。它不是仅封装一个黑盒库，也不是重新写了整套SLAM。旧主线的计算源码对应 NVIDIA v16.0.0；团队在此基础上，重点做了固定参考地图与可控定位、重定位并发和状态恢复、RGB-D CPU/GPU鲁棒性及优化约束。[1][2][4]

今天的 denghw/vio 又加入VO/VIO接口扩展和独立MU后端，但它与已合入 develop 的旧主线必须分开讲。GPU metric priors的实验分支、10月27日未采用的PnP候选，也不能合并成“当前已上线改进”。

这份方案回答三个问题

① 哪些能力继承上游；② 我们在哪些具体文件和机制上做了工作；③ 每项工作现在处于哪个分支、已有何种验证、还缺什么证明。配套 评测方法把这些差异转换成可归因的消融实验。

可以据证据说

  • 主线存在实际算法正确性、地图生命周期和RGB-D求解改动
  • CPU RGB-D是实际计算实现，不只是配置开关
  • 新MU有明确公共基线和额外内部改动
  • 相关测试代码和历史运行证据可追溯

不能据此说

  • 所有分支已发布或实际部署
  • 单项改动已经独立证明精度提升
  • 既有RGB-D实验已运行持续VIO或MU
  • 全部CUDA/特征/回环算法都是团队原创

代码组织中，libs/pnp、libs/slam、RGB-D/VisualICP/SBA和CUDA模块构成核心。我们的工作不是单纯“换参数”，也不是替换整个视觉前端：它改变了参考地图如何参与优化、定位结果如何安全提交、退化帧如何分类，以及CPU/GPU残差和约束的数值行为。[4]

三类贡献不要混写

  • 算法与数值：回环角度计算、协方差缩放、RGB-D约束/退化判断、metric priors、GPU归约。
  • 状态与地图机制：Reference/Session、固定参考关键帧、重定位commit与并发取消、初始化原点。
  • 集成与评测：ROS话题、仿真传感器桥、G2P5重积分、离线评分与归档。它们有价值，但不都位于cuVSLAM算法仓库。

05 / CUSLAM

参考地图定位是这条主线的核心工程机制

Reference 与 Session 的分工

Reference代表可信且冻结的参考地图；Session承载当前会话的新增关键帧和状态。参考关键帧在图优化中固定，地标/关键帧不受在线裁剪或普通更新侵蚀；容量管理与数据库写保护也按此分层。这样固定地图定位不再等价于继续无约束修改旧地图。[4]

接口 / 机制可确认作用必须验证的边界
SetFixedReferenceMap启用固定参考地图语义参考对象不可被删除/更新，Session容量不误计参考对象
FreezeCurrentMapAsReference把当前地图冻结为Reference冻结后新增关键帧属于Session，保存/重载后语义一致
LocalizeInReference查询常驻Reference，默认不写Session成功、失败、取消均不污染Reference；查询耗时与峰值资源
commit_result成功定位后提交并重建Session定位图像时刻之后的VO增量被传播到当前尾部；不能发生时间倒退
取消 + generation + 锁阻止旧加载/定位任务迟到提交交错触发load/reset/localize时，无旧结果覆盖新Session或已销毁对象

质量门控的默认参考匹配数20、比例0.5属于代码默认；修正量上限默认0为关闭。业务launch设定、代码默认和本次实际进程参数必须三者分列。单看接口存在，不能宣称绑架恢复或全局定位已经达到某成功率。

重力原点不能被误写成VIO

初始化姿态进入核心地图，而非只在ROS输出外面乘一个旋转，有助于保证地标、关键帧和导出地图一致。已加载固定地图不允许再次重定向，避免破坏参考坐标。历史RGB-D链路中的IMU只用于这类启动重力对齐，不持续注册IMU测量。[4][10]

06 / CUSLAM

RGB-D鲁棒性不等于把失败隐藏起来

CPU实现与软先验

cpu_icp_tools.cpp/.h不仅补了数据入口，还实现残差、导数与归约。metric SBA priors把VisualICP pose和原始RGB-D点作为软约束，针对弱pitch/Z条件；它们不硬锁位姿，并在优化后检查结果有限且cost未增再写回。旧develop的这一先验只在CPU运行路径启用。[4]

GPU的两次修复处理不同问题

c55bed1补齐“有多少有效depth/point约束”的信息，让退化判断真正执行；5afc677则确保归约累计量从零开始。前者是有效性分类，后者是初始化正确性，不能合并成同一个“PnP修复”，也不能由前者的bag改善记录证明后者的收益。

保留最后位姿必须有状态和时效

瞬时约束不足最多3帧沿用末次pose，是避免过早破坏跟踪状态的恢复策略，不是传感器在这3帧测到了正确运动。评测应分别计：正常视觉估计、TransientUnderconstrained保留状态、数值失败、最终lost、恢复。机器人移动时，陈旧pose可能位置误差迅速增长；上层必须能区分。

CPU源码能力与历史CPU初始化失败不矛盾。

仓库确有CPU RGB-D实现；另一冻结实验配置的CPU测试三次初始化失败，只能说明该构建/运行组合未成功。需要核对构建选项、依赖、二进制和日志，不能据此否认CPU源码实现，也不能据源码存在宣称CPU性能已可用。

新分支里的 VO VIO MU 是三条不同路线

分支内实现，未证实合入develop或部署 denghw/vio@c42fd0a同时维护旧核心扩展和新MU后端，不能把全部新增文件混作一个算法。[5][6]

模式计算结构位置与边界
VO旧VisualICP + visual keyframe BA，CPU/GPU旧核心libcuvslam.so
VIOVisualICP位姿观测 + 15状态ESKF；核心支持外部pose prior、独立feature-search prior、失败保图与按先验恢复ESKF实际实现位于另一个mapping/cuvslam_ros仓库；本轮未逐行审核，不能把完整融合器都归为核心仓库实现
MU独立Multisensor cuNLS位姿求解 + inertial keyframe BA，GPU新libcuvslam_mu.so；无ESKF、无实验三相机窗口；与旧核心ABI重叠不兼容，按文档独立进程

旧核心本次新增的 TrackOptions区分两种prior：影响位姿估计的外部pose先验，与仅供特征搜索的预测先验。RGB-D tracking、VisualICP、SOF传递路径、MapInitialized状态以及约束/残差/Hessian诊断也被修改。初始化状态不应计作视觉运动观测，诊断约束数也不能直接命名为RANSAC内点率。

MU来源与集成边界

multisensor/PROVENANCE.json指定公共commit 41e418a…，已对照；库目录约31个增改路径。构建由 cmake/MultisensorBackend.cmake启动独立CMake工程，要求CUDA≥12.6。目前迁移范围明确是本地里程计和TF；旧地图服务、VPR/重定位、dense mapping尚未接入。

multisensor/third_party/cunls是本地维护源码，CMake对应公开 Release_07_13_2026并指向vendor。本轮未逐文件比较vendor与tag，不能把全部cuNLS代码归为团队原创。“accepted implementation”只表示分支收纳的源码状态，不等于发布接受或生产验证。

以上都是分支源码证据，不是性能结果。各增强之间可能有交互，建议先逐项开关，再测试组合；不得把一次完整MU运行差异全部归因于某一个开关。[5][6]

历史实际链路为 UE5 RGB + SceneDepth / MuJoCo IMU与相对关节TF → Fourier原生cuVSLAM节点 → 原生G2P5节点。它为算法提供系统回归样本，但不是专门算法仓库的全部内容，也不等于标准Isaac ROS部署。[9][10]

项目事实已确认内容解释边界
传感器GR3胸部RGB-D下俯40°；960×600；仿真10Hz RGB-D、200Hz IMU；rgb8/16UC1毫米，scale1000理想完整深度，没有真实空洞/噪声；仿真安装不等于实机标定
IMU与TFRGB-D只用IMU做启动重力对齐；相对关节TF按图像时刻不是持续VIO，也不等于给算法注入世界GT pose
同步与运行use_sim_time=true；容差1ms；预热10帧；use_zero_copy=false存在零拷贝接口不代表实验用了零拷贝
定位与地图输出odom、robot_pose、slam_path、状态/质量；G2P5为5cm栅格各输出语义要核对；地图原图与美化图评分分开
路线与GT真值用于驱动路线、预建导航图和离线评分全屋走完不是用新SLAM地图自主导航的证明；GT隔离还需启动挂载审计

已有相关测试源码与历史回放、10户型批量归档。本轮只是读代码和归档，没有运行测试。10户型来自100个冻结布局中抽10户，8户可评测、2户前检不可达；严格采集/零环境接触通过0/10。8户宏平均在线全局SE2 ATE 0.4198m，而固定起点位置RMSE 0.9145m；输出可用99.864%，固定起点正确时间52.07%。这说明“持续有输出”仍不等于“可依赖的定位”。[11]
