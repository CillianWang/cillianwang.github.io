归档定位与结论

本归档确认了可读资料中的设计脉络，未确认 Monitor 最新部署状态。

本次在 Mac 上找到了 Fourier Monitor 的 26 份相关历史主题记录，并直接阅读 Wizard 与 fourier_perception 的 5 份现存集成源文件。原项目 /Users/pingy/code/fourier_monitor 及名称变体 fourier-monitor 未在已搜索的相关位置找到，故无法提供 Monitor 自身当前 HEAD、工作树差异或完整路由清单。历史笔记中的“已验证”均指当时记录，不是本次重新运行的结果。

项目是什么

机器人端统一运维与调试界面：将进程可用性、DDS 图、任务/能力状态、执行器、故障与日志，以及感知/头域/IMU 专项可视化汇集到浏览器。

[S01] [S03]

核心设计

C++ 统一服务与监控引擎、按功能隔离的 DDS 订阅子进程、线程安全 Hub、HTTP/SSE API、浏览器数据驱动页面。unified_web 是历史 CMake target，安装产物沿用 grmonitor。

[S01] [S10] [S13]

最重要的边界

Monitor 展示与发起控制请求；fourierpc 执行进程启停，grstate 裁决任务与能力，Aurora 执行底层控制。进程可达、业务健康、命令完成和物理安全不是同一事实。

[S20] [S26]

本次核验范围

只读检索、逐主题内容核对、现存集成代码核对和 HTML 自检。未拉取远端仓库、未接机器人、未启动生产服务、未编译或部署 Monitor。

现存代码 本次可直接读取的本地文件。 历史记录 过去的设计/实施/现场记录。 建议 本归档提出，尚未实施。 待确认 当前证据不足。

所有源码与日志路径仅用作追溯，不携带秘密值；本文件不依赖这些路径存在才能阅读。原项目缺失是证据完整性限制，不影响本次设计归档交付。

02 · Why it exists
回到顶部 ↑

用途、需求与责任边界

它解决的主要问题是：同一台机器人上多进程、多 DDS 平面、多类日志和多种控制入口彼此独立，现场人员很难区分“进程启动了”“服务有应答”“状态还在更新”和“动作真的完成了”。设计把这些证据放在同一入口，同时保留各自来源。

需求设计回应责任边界
快速判断系统是否可用registry 进程表、CPU/内存/运行时间、introspection 与 /proc 双证据不能以某一条 RUNNING 判定整机健康。
解释任务为何不能执行grstate runtime report 的任务、capabilities、suppressions能力裁决归 grstate；Monitor 不制造允许状态。
定位硬件与传感器异常执行器字段、HMS 故障、IMU/头域/感知专页沿用源数据语义与新鲜度，不把空数据解释为正常。
减少现场收集证据的步骤模块日志下载、时间窗 ZIP、状态回放、热测试 CSV、FDI 触发几类录制的对象、生命周期和完成条件不同。
兼容真机、仿真与代理访问单服务产物、磁盘静态资源、Wizard 的配置重写代理仿真入口能访问页面不等于所有 Monitor API 均可用。

[S01] [S03] [S08] [S15] [S14] [S16] [S27] [S29]

明确不在已证实范围内：底层 RL 模型/策略推理的监控、独立安全控制器、完整遥测数据湖、持久化全部原始 DDS 消息，以及对所有机器人型号/分支统一通过的验收。历史记录明确说，policy_change_service 的 RPC 名可见并不代表其 payload 或当前 policy.pt 可见。[S26]
03 · One entry, several evidence paths

系统架构

早期独立 grmonitor :18080 与 task_runtime_web :18081 合并为统一服务；历史合并记录中 ProcessMonitorManager 以无头模式嵌入（monitor_center.http_port=0），统一 HTTP 常见端口为 18085。这是迁移设计；实际安装版本仍须核对，Wizard 当前入口保留旧端口与旧能力兼容。[S01] [S28] [S29]

子进程模式为类型支持与运行时依赖提供隔离边界。例如头域工具链接 GrcsRequest，Reader 将 stdout JSON 行写入有界 Hub；主服务不必直接链接该消息的 typesupport。感知后期采用 vendored Viewer 的 HTTP 快照桥接，不应仍画成早期 JPEG JSON 行链路。[S10] [S12]

05 · Follow the evidence
回到顶部 ↑

关键数据流与控制流

① 进程健康

registry → introspection RPC → service_alive / 自报 PID → 本机 /proc → CPU、内存、uptime → /api/processes。

历史采样约 2s、RPC 超时约 150ms；Aurora 无匹配规则时失联可直接显示 SERVICE_UNAVAILABLE，即使控制循环仍正常。

[S04] [S05]

② 任务与能力

grstate_runtime_report → runtime_report_sub → RuntimeReportReader → /api/state + /api/events → 能力/任务/事件页面。

状态为空先区分源进程缺失、DDS 未匹配、数据陈旧和代理断链，不应由 UI 的固定 source 标签推断有新数据。

[S26] [S27]

③ 进程控制

POST /api/start|restart|stop → ProcessMonitorManager → process_monitor_control → fourierpc → process_center。

STOP 先将 desired_running 置 false 再停止进程；意图状态使监督器不把人为停机当作异常退出。Kill All 是另一条本地终止链。

[S20]

④ pad 速度

VelocityCmd + source=pad → GrgosGatewayClient → :8001/ws?source=pad → grgos → grstate。

历史实现采用持续 WebSocket、50Hz 脉冲、hold 400ms + zero-release 600ms；其余来源沿原发送链。仅给 payload 标记 pad 不等于经过网关。

[S19]

⑤ 只读诊断

hms.db → HmsDbReader → 结构化故障/状态；配置目录 → readdir/stat → 元数据/下载/ZIP。

Monitor 也曾向 HMS 发布自身 snapshot/event；不能因 Monitor 展示 HMS 数据，就把所有数据生产职责归给 Monitor。

[S08] [S18]

⑥ 版本化感知

status.snapshot → 指定版本 FPS1 bundle → 验证 metadata + RGB + depth → 一次应用快照 → Canvas 叠加。

本次直接读到的上游解析器检查 magic、长度、snapshot_version 与 timestamp_ns。它印证协议设计，但不证明某台 Monitor 已部署相同版本。

[S12] [S31]

/api/recordings/upload、package[s]会话快照上传与服务端包管理前端回放已有历史验证；二期记录有代码完成但全量构建待证。[S15] [S16]

07 · What each value means
回到顶部 ↑

数据模型与一致性契约

数据对象字段 / 结构必须保留的语义
进程快照service_alive, proc_alive, service_pid；名称、CPU、内存、uptime；托管 matched/desired/restartable自报 PID 有主机作用域；managed 查询失败不应被折叠成确切的 false。历史 UI 曾出现该歧义。[S04] [S20]
任务报告main_state, task_state, aurora_task_runtime, capabilities, suppressionsschema 属于 grstate；高层行为态不等于神经网络策略内部状态。[S26]
执行器name, joint_name, position, velocity, current, torque, mos_temperature, armature_temperature, voltage, error_level, error_codes, actuator_type, sub_version, firmware_version关节名从当前硬件配置映射；非零原始 error word 不可统一判故障。[S03] [S09]
头域消息GrcsRequest，方向、时间、消息 id、解码字段；UUID 为 16-byte 数组转 hex原始 DDS 消息与 grgos WS 的状态投影不同；消息总数不可跨语义直接对比。[S10] [S11]
IMUorientation(x/y/z/w), angular_velocity, linear_acceleration, bias_vector, frame_id四元数为单位值不必然代表真实水平姿态；历史雷达源只报 gyro/accel，单位 g 与本体 m/s² 不同。[S13]
FPS1 快照16 字节头；magic + 3 个大端 uint32 长度；metadata JSON + RGB + depth 字节当前上游：metadata ≤1MiB，单图 ≤8MiB；精确总长度、版本、时间戳必须一致。[S31]
会话回放按 API key 分组时间线 + SSE eventLog；回放墙钟；每 session 去重/裁剪通过 fetch/EventSource 返回历史数据重画 UI；回退 seek 必须重建 append-only 事件游标。[S15]
热录制ISO 时间、epoch_ms、板载温度/功率/CPU 负载、关节温度及可选 Thor 列新会话 started_ms 改变要清本地历史；旧温度超过新鲜度门应为空/陈旧。[S14]
FDI 状态event_key、state、source、可选工单链接含斜线的 key 要跨代理正确编码；unknown 可继续轮，skipped 需结束，成功阶段应明示。[S16]

执行器故障例子

历史修复把“任一 error_codes 非零即异常”改为按 FSA 槽位解释：error[1] 为 1/2 可以正常，error[7] 超时属于 warning 口径；error_level 与上游映射共同决定展示。不能把 raw bitfield 的数值大小当成严重程度排序。独立的 UI 固定高温阈值曾被移除以对齐 HMS；热测试页面的温度展示与硬件故障告警是两件事。[S09]

监控、告警与可视化

观测层页面 / 指标解释限制
进程 / 资源Name · CPU% · Memory · Uptime · PID；RUNNING / PROC_ONLY / SERVICE_UNAVAILABLEPROC_ONLY 可是无 introspection 的正常网关。RPC 失联不能直接推导控制循环已死。[S03] [S05] [S04]

硬件执行器表/曲线、错误码与固件版本、HMS 结构化故障列表不要以未收到样本或默认值解释为健康。[S09] [S08]
感知RGB/深度、bbox/抓取叠加、目标槽位、matched/live/waiting/error 诊断必须同帧；示意手模型与真实手模型分开；任务按钮映射有未逐项确认记录。[S12]
IMU地平仪、罗盘、RPY、四元数、三轴时序、实际输入频率源频率与 UI emit 频率不同；历史工具限流 50Hz，原输入曾记录 500/200Hz。[S13]
热测试温度/功率/风扇/CPU busy 时序，CSV 导出每像素桶取 max 以保留峰值；历史数据新鲜度门 60s。[S14]
性能扩展（分支限定）develop 的 CPU p95/p99、线程、IO、context switch、资源告警与 rollup2026-07-07 合并记录存在；本次无法确认各发布线和设备是否包含。[S24]
告警边界：检索到的是页面健康色、结构化故障/事件、性能告警字段与 FDI 工单触发。未找到可据此确认的统一告警路由、通知策略或全局 SLO 配置；不补造 Prometheus/Grafana/Alertmanager 集成。
09 · Readable under pressure
回到顶部 ↑

前端结构与交互设计

Monitor 的历史视觉语言是深色玻璃卡、侧栏、等宽元信息与状态色。这里归档的是信息架构与渲染边界，不复刻运行中控制台。后期首页只保留系统状态；能力层与执行器各自成为独立侧栏页面，渲染受 active panel 门控。[S03]

从单文件到按序脚本

home.html 曾从约 7948 行拆到 540 行。CSS 外置；app.core → app.home → app.events → app.console 使用经典 script 共享全局，boot 最后执行。延迟逻辑中的解析期向前引用是拆分时的真实约束。

[S02]

保持用户视线稳定

感知目标卡按 id 维护稳定槽位、原地更新，消失时先变暗；后期记录补充 30s TTL 后删除，重现视为新条目。图像保持宽高比而非填满裁剪。

[S12]

减少后台消耗

visibilitychange 暂停背景动画，reduced-motion 降低动态效果；IMU 页面离开即停止/超时回收订阅。减少嵌套大 blur 与全屏混合层，避免切回标签时的大规模重光栅化。

[S02] [S13] [S25]

缓存契约也是接口

部分发布线由 ?v= 改为 styles.vNN.css 等路径版本化，服务端映射回 canonical 文件。不同分支混用二进制和资源会导致 404 或旧缓存，必须作为同一发布单元。

[S23] [S12]

操作者标识由 console 代理注入配置，再由 operator.js 写到同源非 GET 请求头；中文值 URL 编码、服务端清理控制字符。这是审计归因，不能代替身份认证与授权。[S17]
