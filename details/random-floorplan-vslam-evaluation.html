01 / SCOPE

先评“同一段观测”，再评“自主探索”

固定回放

预录同一批图像、深度与时间戳，算法只看允许的输入。适合比较定位误差、失跟和运行开销。

闭环系统

算法估计影响控制与路径。适合评机器人任务成功率，但也混入规划、控制和避障差异。

两张成绩单

不要把导航任务完成率与离线轨迹 ATE 混成一个未经定义的“SLAM 分数”。

第一版建议采用固定回放 benchmark：同一个场景与轨迹只渲染一次，然后把完全相同的字节交给每个算法。真值和场景语义只供评测器使用；RGB-D 的深度输入是传感器观测，不等于可访问真值轨迹或真值地图。

TUM 的经典基准以独立真值比较输出轨迹，区分局部运动误差与整体轨迹一致性；它并不把内部重投影残差当作最终定位精度。[1]

02 / DATASET DESIGN

分开随机数，才能知道是谁让算法失效

随机因素控制什么建议保持不变的对照
topology_seed外轮廓、房间邻接、走廊、门、连通性外观和路线不变，隔离几何难度
appearance_seed材质、纹理、物体实例、灯光；可再细分子种子相同户型、相同轨迹换外观
trajectory_seed起终点、访问顺序、闭环与速度曲线同一场景观察不同运动影响
dynamics / noise_seed行人轨迹、门的动作；相机与深度噪声同一底片配成静态/动态或理想/带噪声条件
algorithm_run_seed算法内部随机性；不一定能控制线程调度所有算法共享同一输入，而不是重新渲染

一个“大种子”并不足够。生成器增加一次随机抽样就可能改变之后所有内容；应使用具名的独立随机流，并保存最终场景、轨迹与传感器数据的哈希。种子用于重建，冻结文件才是这次比较的依据。

按场景族划分，而不是按图像划分

  • Train：仅当方法需要学习时使用；不学习的方法也不能利用测试集真值选参数。
  • Dev：调参、选择噪声模型、发现适配错误；先在这里确定失败定义、过滤条件和评测口径。
  • Test：冻结后只做最终评测。相同基础户型的改纹理版、旋转版、镜像版、不同轨迹都属于同一个 scene_family_id，不可跨集合泄漏。
  • 分开回答两种泛化：“未见几何、相似家具库”与“未见几何 + 未见材质/资产族”是不同的测试；后者单独标为 OOD。
冻结的最小单元

split manifest → scene/asset revision → trajectory/rig → sensor profile → frame/pose files → hashes。把 split 列表与生成器版本一起归档；测试后发现坏数据，用有版本号的纠错清单修复并对所有算法重跑，不能只删掉某算法失败的样本。

03 / MOTION

先保证“能走”，再保证“值得测”

二维户型图本身不能直接评视觉 SLAM。至少需要有尺度的三维墙体、门洞、天花/地面、合理材质和相机可见的遮挡关系，再为机器人足迹建立可通行域。

  1. 几何体检检查门洞净宽、墙体厚度、家具穿插、封闭房间与悬空物体。按机器人半径 + 安全余量膨胀障碍；足迹、机身高度、相机高度分别检查。
  2. 可达性验证在同一个可达连通分量内采样起终点，验证路径存在。记录不可通行场景的生成拒绝率，而不是用算法是否能跟踪来决定场景是否有效。
  3. 生成路线族短程无闭环、跨房间长程、返回起点闭环、相似走廊、原地转向、遮挡后回到已建图区域。难度按门数、转角数、长度、可见区域变化等描述。
  4. 连续运动与碰撞复查给路径做速度/加速度/角速度限制。平滑后重检与墙和家具的距离；不能把折线路径直接当成瞬时旋转的相机轨迹。不要每一帧随机传送。
  5. 保存实际相机位姿如果有物理仿真，记录执行后的真实 body pose，再乘相机外参；不要拿控制指令、规划路径或里程计当真值。

Habitat-Sim 的 PathFinder 提供 NavMesh、路径、点采样、障碍距离与连通岛查询，可作为静态可通行路线的工具；它不替代对具体机器人完整碰撞体和动态物体的验证。[8]

对比闭环时，固定机会，而非强行保证识别成功。

根据真值位置、视角和可见重叠定义“闭环机会”；算法是否正确闭环才是结果。机器人没看过同一个地方，不应算成回环检测失败。6-DoF 手持/飞行轨迹与平面底盘轨迹分榜，不用不可能的运动给底盘制造难题。

04 / OBSERVATIONS

传感器赛道分开，理想真值不等于真实传感器

赛道允许的算法输入必须补齐的契约
Monocular单相机图像、内参、时间戳无额外尺度先验时绝对尺度不可观；主榜 Sim(3)
Stereo同步左右图像、内外参基线的米制单位、左右顺序、校正前/后内参与畸变
RGB-D彩色 + 传感器深度深度单位、Z-depth 或 ray range、无效值与范围、配准状态
Visual-inertial对应视觉赛道 + IMUIMU 坐标、相机外参、采样率、时偏、噪声与 bias、重力方向

同一算法的不同传感器配置也应独立列项。不得将 RGB-D 的理想深度用于单目输入，也不得让基线算法读到语义 mask、相机真值或生成器地图，除非另立“有额外先验”赛道。ORB-SLAM3 提供多种视觉与视觉惯性配置，是可选的对照候选，不代表它已在 Wizard 中可运行。[5]

理想控制组

无噪声、固定曝光、已知 pinhole 内参、严格同步、无动态。先证实格式、标定、坐标和度量工具没有错误。

现实压力组

加入曝光变化、运动模糊、光子/读出噪声、压缩、深度空洞和量化。逐项验证后再组合；参数来自目标相机测量或明确标为假设。

渲染时至少保存这些信息

  • RGB 色彩顺序、位深、分辨率、FOV/内参、畸变、裁剪范围；resize/crop 后同步更新内参。图像去畸变与算法畸变参数不能重复生效。
  • 光源位置与强度、曝光/增益、tone mapping、渲染模式/采样数、动态对象轨迹和版本；不要把纯随机噪声纹理当成真实室内纹理。
  • RGB-D 保存原始深度语义。若返回光线距离 r，对 pinhole 相机可用 Z = r / sqrt(1 + x_n² + y_n²) 转为光轴深度；有畸变时先取得正确射线方向。
  • 理想 geometry-depth 与模拟传感器-depth 分别存放。反光/透明材质、边缘、遮挡和测距范围的失效模型要独立说明。

Isaac Lab 文档明确区分光轴深度 distance_to_image_plane 与到光心的欧氏距离 distance_to_camera。Isaac Sim 当前相机文档已迁移到 RtxCamera / CameraSensor；本文不提供未经版本验证的仿真 API 代码。选定版本后固定其传感器与渲染接口。[9] [10]

可选 IMU 不宜用“相邻位姿粗差分”草率生成。

应从平滑、足够高频的真实运动产生角速度和含重力关系的比力，再叠加记录明确的 bias、噪声密度与随机游走；单位分别为 rad/s、m/s²。配置静止及有激励的初始化片段，并单独计初始化失败。滚动快门则需要行读出时序；单个帧中心位姿只是评测约定，不是整张图的瞬时物理真值。

05 / GEOMETRY & TIME

一开始就写清楚 T 的方向

本文统一采用列向量与 T_A_B 命名：把 B 坐标中的点变换到 A 坐标。右手世界系 Z 向上；相机光学系 x 向右、y 向下、z 向前。若引擎采用另一种相机轴向，先做固定基变换，再导出。

p_world = T_world_camera · p_camera
T_world_camera = T_world_body · T_body_camera
T_camera_world = inverse(T_world_camera)
若 T = [R t; 0 1]，则 T⁻¹ = [Rᵀ −Rᵀt; 0 1]

逆变换不是简单把平移取负，也不是把四元数顺序换一下。相机光心与机体/IMU 原点可能相差几十厘米，尤其转弯时不能混评。ORB-SLAM3 的 EuRoC 说明特别区分 IMU-body 真值与纯视觉左相机轨迹；标定文档定义了相机光学轴与传感器外参。[5] [6]

TUM 风格导出约定

# timestamp_s tx_m ty_m tz_m qx qy qz qw
# pose = T_world_camera；四元数为单位四元数，顺序 xyzw
# 以下仅说明格式，不是采集结果。
1700000000.000000000 1.0 2.0 0.8 0.0 0.0 0.0 1.0

TUM 文件的相机位置/朝向相对于世界，时间以秒表示，四元数为 qx qy qz qw。本方案可设一个固定的合成 Unix 起点，但要显式标记“合成起点”，不是声称采集于该日期。[2]

同步必须与图像采样时刻一致

  • 内部优先存整数纳秒；导出秒时检查精度。所有传感器和 GT 使用同一仿真时钟，单调递增、无重复戳，显式记录曝光中心/开始/结束。
  • 位姿关联到图像对应的采样时刻，不是渲染结束时间或算法输出到达时间。后者另存为 latency。
  • 同步左右相机、RGB 与 depth；IMU 保留自己的高频时间轴和外参。若故意加入时偏，按压力条件记录，不能为每个测试序列用 GT 重新“调到最好”。
  • 高频 GT 可在相机曝光时刻采样；必要时平移插值 + 旋转 SLERP，并记录插值策略。不要跨越缺测、失跟或 reset 的大间隔插值算法轨迹。

EuRoC 官方数据含同步视觉/IMU、标定与真值，也公开了曝光和记录系统同步的限制。它可作为格式和现实复杂性的参考，不意味着合成数据只要长得像 EuRoC 就完成了标定。[7]

三项小测试，先于任何排行榜：

相机前方 1 m 的点应投影到正确像素；已知 1 m 平移应在 GT 中恰为 1 m；导出 T 与 T⁻¹ 相乘应为单位阵。再用已知正向旋转检查图像方向、四元数顺序及左右手系。

06 / ACCURACY

ATE 看全局，RPE 看局部；口径比小数点更重要

记真值相机位姿为 Qᵢ，已统一时间/坐标约定的估计为 Pᵢ。先固定关联集合、有效样本范围、对齐方式、区间与单位，再算误差。

ATE / 平移 APE

对齐后逐时刻位置偏差的 RMSE（m），另列 median / P95。反映全局轨迹一致性；不能单凭它推断地图质量。

ATE = sqrt(mean(||qᵢ − p̃ᵢ||²))

RPE

比较两个时刻间的相对运动，主统计为平移 RMSE（m）与旋转 RMSE（deg），附 median/P95。说明是 1 m、5 m、1 s 还是固定帧间隔。

Eᵢⱼ = (Qᵢ⁻¹Qⱼ)⁻¹(Pᵢ⁻¹Pⱼ)

以上分别对应 TUM 轨迹误差思想与 evo 的 APE/RPE；evo 是通用工具，不是某一数据集协议的逐项复刻。[1] [3] [4]

情形建议主口径不能掩盖什么
有度量尺度：Stereo / RGB-D一个全局 SE(3)，仅旋转和平移；不允许优化尺度错误 baseline、深度尺度或算法尺度漂移
无额外尺度先验的单目一个全局 Sim(3)；独立单目榜单“几何形状好”不等于恢复了真实绝对尺度
视觉惯性度量主榜不做尺度修正；初始化失败独立记录全 SE(3) 会吸收常量倾斜；可补充重力方向误差及 yaw+平移对齐，明确另列
在线漂移/闭环分析附加固定起始对齐或预注册初始化窗对齐整段最小二乘对齐使用了未来 GT，不是在线定位性能

单目的尺度要怎么报告？保留全局 Sim(3) 的拟合尺度 s（估计单位 → 米）与时间窗口尺度变化；窗口拟合只作诊断，不用于逐段修正主成绩。单目原始单位本来任意时，不能把 |s−1| 直接解释成物理尺度错误。若有外部尺度先验或固定初始化尺度，单独列出其来源和无后续尺度修正的误差。

把 RPE 的“每米 / 每秒”说准确

  • 建议主 RPE 采用按真值累计行程选出的 1 m 区间；另测 5 m 区间看中程漂移。固定 all-pairs/不重叠策略、区间容差、有效 pair 数和真实间隔分布。
  • “1 m 区间的平移误差”单位仍为 m，“1 m 区间的旋转误差”仍为 deg。若报告百分比或 deg/m，必须按每个 pair 的真实距离归一化，再汇总；不是换一个标签。
  • 当前 evo CLI 的 --delta_unit 支持 f / d / r / m，没有 s。要评 1 s，用明确的时间戳配对器；只有严格等间隔、完整无缺帧的 30 Hz 序列，30 帧间隔才等于 1 s。[11]
  • 刚体全局对齐不会改变相对运动；尺度修正会改变平移 RPE。单目应先应用同一个全局拟合尺度再算 RPE，绝不能每个片段重新拟合最优尺度。
不默认投影为 2D。

平面机器人仍可能有俯仰、颠簸和相机高度误差。主榜使用 3D 位姿误差，另附 XY 可视化。低 ATE 不证明回环“都正确”：保存回环时间、优化前后误差、错误闭环导致的轨迹跳变。

07 / RELIABILITY

只对成功轨迹算平均，会奖励早早退出的算法

每个预定 run 必须出现在结果表中，包括初始化失败、失跟、崩溃、超时和没有输出。缺失误差记为 NA + 原因，而不是 0；失败 run 仍进入成功率的分母。

指标建议明确定义报告方式
完成率预注册完成条件，例如跟踪比例 ≥95%、最大连续缺口 ≤2 s、到达最后 1 s 窗口且未崩溃通过 run 数 / 所有预定 run；同时报告条件阈值。此处数值仅为起点建议；不代表精度合格
跟踪比例固定评测时间网格上的有效在线位姿数 / 全部应有样本数从序列开始计；初始化等待时间不悄悄删掉；明确“自报 tracking”还是经真值验证
失跟连续无有效估计或算法报告 lost 的时间段次数、总时长、最长时长；时间网格容差固定，不以关键帧稀疏度冒充失跟
重定位预定义遮挡/离开视野后，回到已建图区域，恢复到原地图坐标并满足误差门限，持续一个固定窗口成功率、耗时、错误重定位数；创建新地图不是自动算成功
覆盖率固定 GT 网格/房间中的有效跟踪访问覆盖，或已观测表面覆盖；定义分母与可见性与时间跟踪比例分开；固定回放的路线覆盖由数据决定，不能当算法的探索能力
计算开销固定硬件与线程下，输入到在线位姿的延迟、吞吐、CPU/GPU 与内存峰值median/P95、实时截止期违约、丢帧与队列；仿真渲染时间与 SLAM 时间分开

完成不等于准确。上述完成率只衡量运行与跟踪可用性；若称为“定位成功率”，还要在 Dev 上预注册位置/姿态误差门限及持续时长。下文的成功 run 必须注明采用“完成”还是“精度合格”标准，不能混用。

部分轨迹与 reset 的处理规则

  1. 全体 run 的可靠性先报。再报“成功 run 条件下的 ATE/RPE”，同时给出成功数；另附所有部分轨迹误差、有效时长与路径长度。它们不能直接作为无条件精度排名。
  2. 每条轨迹只用一个全局对齐。失跟后 reset 成多个地图坐标时，必须说明 map_id；无合法全局拼接关系则整条 run 不具备单一全局 ATE。片段误差只能作为诊断，不能独立对齐后冒充完整成功。
  3. 不得虚构缺失轨迹。不以最后位姿填满未来、不跨长缺口插值、不删除高误差片段。RPE 只在连续有效区间内配对，缺口两端不得强连。
  4. 在线与最终优化后轨迹分开。最终重优化的历史轨迹不能冒充当时可用于控制的在线输出；最终轨迹的稀疏关键帧精度也不能替代逐帧跟踪可用性。
  5. 区分数据无效与算法失败。坏相机内参/渲染缺帧属于数据管线错误，按统一规则处理所有算法；同一输入上算法崩溃则属于方法结果。不要事后按排名修改判定。
推荐一行结果字段

scene_id, condition_id, trajectory_id, run_id, status, initialized, tracking_ratio, max_gap_s, map_resets, ate_rmse_m, rpe_trans_rmse_m, rpe_rot_rmse_deg, num_pairs, alignment, fitted_scale, latency_p95_ms, peak_memory_mb, failure_reason。字段为空时保留原因；不要编造一个“代表性成绩”。

08 / EXPERIMENT MATRIX

先单因素，再组合压力；用成对实验比较

维度建议条件主要观察
几何长走廊、窄门、连通环、相似房间漂移、闭环机会、错误地点识别
纹理均匀墙面、重复纹理、自然纹理初始化、特征退化、误匹配
光照明暗房间切换、局部强光、曝光变化失跟、恢复、视觉/深度差异
运动慢速 / 快转、前向移动、低视差、局部纯旋转可观性、模糊、初始化失败
动态可控行人数量与遮挡占比、门动作静态背景比例、失跟和错误地图
回环无回环、短回环、长回环、相似但不同的房间闭环前后漂移、误闭环、修正耗时
传感器深度空洞、噪声、丢帧、时偏、滚动快门精度/可用性对单项退化的敏感度

建议统计设计 以相同 scene × trajectory × condition × sensor bytes 对齐所有算法。每个场景多条路线，算法重复运行以反映随机性；“同场景跑 20 次”不是 20 个独立户型。

  • 先在每个场景内汇总重复 run 与轨迹，再做场景等权 macro-average；按户型大小、路线长度和难度分层报告，避免长序列或大场景占据全部权重。
  • 比较 A 与 B 的成对差值，并展示分布。置信区间可用以场景族为簇的 paired bootstrap；避免把数十万帧当作独立样本。
  • 成功率比较用全体成对 trial；双方均成功时的精度差只是条件分析，需要同时列出单边失败数。
  • 固定 CPU/GPU、线程、版本、功耗设置、输入速率和最大队列策略。硬件负载会扰动时延，应交错/随机化运行顺序，记录每次运行环境。
  • 提前冻结超时与重试政策。基础设施故障可以有记录地重试；算法崩溃不能“重跑到成功为止”。若存在线程非确定性，即使固定随机种子也要保留多次结果。

以下是评测命令示例，不是 benchmark 实现。

命令不会自动生成数据、检测失跟或完成公平排名。必须先执行上述数据验证与失败策略。0.001 s 是严格同步合成数据的示例关联容差，不是通用推荐；真实数据需要独立标定的时偏与预注册容差。

# 示意命令：先有经验证的 TUM 格式输入；本文没有执行这些评测。
# 下列参数按 2026-10-29 查阅的 evo 官方文档/解析器核对。
# 正式实验固定 evo 版本；再检查该版本的 --help。
evo_ape tum --help
evo_rpe tum --help
mkdir -p results

# 1) 度量模式：Stereo / RGB-D（或已初始化的视觉惯性）
# 一个全局 SE(3)，不修正尺度；输出平移 ATE，输入单位为米。
evo_ape tum gt_camera.tum est_camera.tum \
  --align --pose_relation trans_part --t_max_diff 0.001 \
  --save_results results/ate_se3_algorithm_A.zip

# 2) 无尺度单目：单独的榜单，允许一个全局 Sim(3)。
evo_ape tum gt_camera.tum est_mono.tum \
  --align --correct_scale --pose_relation trans_part \
  --t_max_diff 0.001 --save_results results/ate_mono_sim3_algorithm_A.zip

# 3) 度量尺度输入的 RPE：按真值行程选择 1 m 的重叠区间。
# 单目须预先应用同一个全程拟合尺度；下列命令不会自动缩放。
# seg 是事先按 lost/reset 日志分出的连续段；不得跨失跟区间配对。
evo_rpe tum gt_seg.tum est_seg.tum \
  --pose_relation trans_part --delta 1 --delta_unit m \
  --all_pairs --pairs_from_reference --delta_tol 0.1 \
  --t_max_diff 0.001 --save_results results/rpe_1m_trans.zip

evo_rpe tum gt_seg.tum est_seg.tum \
  --pose_relation angle_deg --delta 1 --delta_unit m \
  --all_pairs --pairs_from_reference --delta_tol 0.1 \
  --t_max_diff 0.001 --save_results results/rpe_1m_rot.zip

# 4) 只合并同一指标、同一口径的结果，不把 ATE 与 RPE 混在一起。
evo_res results/ate_se3_algorithm_*.zip --save_table results/ate_se3_table.csv

11 / EXECUTION PLAN

四阶段推进，比直接生成一千套房子更稳

以下数量是用于估计工作量的建议起点，不是统计功效结论，也不是已运行规模。

  1. 阶段 A · 管线自检：3 个小场景空房、带门两房、简单闭环。确认 1 m 尺度、图像投影、T 方向、时钟、深度语义与算法输出。用 GT 直接对 GT 的离线评测应近零；人为插入已知刚体/尺度变化，检查对齐是否按规则生效。
  2. 阶段 B · Dev 试验：约 12 个场景族每场景 2–3 条路线，选择一个已适配的基线，先理想控制组再单项压力。确定初始化片段、运行超时、成功定义与主指标；统计生成拒绝率和失败类型。
  3. 阶段 C · 冻结 Test：例如 60 个新场景族按几何/路线长度分层，每个算法使用相同数据，先以 3 次重复 run 估计随机性。根据开发阶段方差和目标效应选择正式样本量，不能看到 test 排名后再挑规模。
  4. 阶段 D · 现实锚定在对应传感器配置上跑 TUM / EuRoC 等真实数据，再用目标机器人采集有独立真值的小样本。观察排序与失败模式是否一致；若不一致，先诊断域差异，不调 test 去“对齐结论”。

建议产出，而不是只留一个排名

  • 协议包：split、scene/sequence manifests、传感器配置、版本、哈希、有效性规则、失败政策。
  • 原始结果包：全部在线/最终轨迹、状态、回环/重定位事件、运行日志与资源数据。
  • 分析包：全体 run 表、场景等权统计、成对差值与置信区间、分层曲线和失败案例；没有测试结果的地方保持空白。

13 / LIMITATIONS

随机户型能扩大覆盖，不能自动消除域差异

它最适合回答“在已控制的几何、纹理、运动和噪声条件下，哪一种失败因素更敏感”，并提供回归测试。它不能单独证明机器人在真实住家、镜面玻璃、真实曝光与同步误差下同样可靠。

可以较有把握地比较

同一冻结输入上，某个代码/参数变化是否改善局部漂移、减少失跟，是否在重复纹理或明暗切换下出现退化。

需要实测再下结论

绝对落地精度、安全性、真实相机噪声鲁棒性、用户环境成功率，以及合成排行榜能否迁移到目标硬件。

逼真渲染、随机材质和更多场景数量都不是充分条件。应对照目标传感器的图像、噪声、曝光、运动与失败样本校准分布；真实数据用于外部检验，不能反向泄漏到已冻结测试集。

最小可信结论的模板

“在协议版本 X、传感器赛道 Y、冻结场景集合 Z、相同输入和硬件预算下，报告所有 run 的成功率，并在明确的有效轨迹范围内报告 ATE/RPE；该结论尚需目标机器人真实数据验证。”
