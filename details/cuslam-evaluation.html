01 / CUSLAM

评测内部改动，而不是重跑一个通用榜单

核心问题：专门的 perceptionnav/cuvslam 仓库相对其可确认上游或冻结基线改了什么，这些改动是否改善了原生 RGB-D 定位、回环/地图一致性和端到端资源开销？每一项改动都应有可复现的消融，而不是只给“最终版看起来更好”的视频。

实际链路是 NVIDIA 核心 + Fourier cuvslam_ros_node + dense_mapping_node/G2P5。RGB-D 路径中的 IMU 仅用于初始化重力对齐，不是持续 VIO。核心算法、ROS 工程封装、稠密/2.5D 建图和评测改进必须分栏归因。[7][8]

本页三种标签

已有证据 指归档中可查的历史实验；建议协议 是下一轮应执行的实验；“未验证”表示接口或假设存在，但本轮没有成功率或因果证据。本文未运行新 benchmark。

与 内部仓库方案与开源差异梳理配套使用：先确定改动和基线，再固定评测。旧主线基线已通过文件级对照确定为公开v16.0.0；新MU另以公共commit 41e418a…为基线。两个基线不互换，内部重写Git历史也不等于公共提交相同。[16][17]

02 / CUSLAM

先冻结版本与因果对照

使用归档里的核心/封装提交、二进制 SHA-256 和完整运行配置建立基线。仅写仓库 branch 或 package.xml 的 0.0.1 不足以识别核心版本；源码 commit 与执行二进制需要有构建凭据连接。[7]

对照要保持相同回答的问题
内部冻结核心 vs 单项核心候选同 sensor bundle、封装、G2P5、GPU/CPU、编译选项、运行顺序策略该算法补丁是否改善正确时间/漂移，而非环境差异
旧 G2P5 vs 历史位姿重积分版完全相同最终历史位姿和深度输入地图更新是否等价于从最终位姿重新积分；不推断定位精度
核心 × 地图的 2×2 组合分别冻结旧/新核心与旧/新地图实现定位变化和地图积分变化的交互，防止混合升级归因错误
内部分支 vs 开源上游使用已确认v16文件级对应或MU明确公共基线；适配器输入/输出和预处理公平可识别的内部差异是否带来净收益；两个后端和两个公共基线不可混用
RGB-D 初始化重力对齐开/关相同起始姿态与观测，明确是否更改坐标初始化姿态初始化收益；不能称 VIO 消融
零拷贝开/关确认真实消费路径、相同输入、独立日志和拷贝成本工程性能改进；原实验 use_zero_copy=false，不能追认已生效

状态审计：每个改动记录“已入冻结运行版本 / 已合入源码但未跑 / 实验候选 / 已拒绝 / 归属未证实”。源码存在和提交已合并都不等于当前线上在用。下面的逐改动矩阵来自已完成的源码审阅；每次实验选择对应commit或开关填入 change_ids。

应冻结的最小版本包

  • 核心、wrapper、mapping 的 commit、工作树 diff、构建类型、编译选项、依赖与容器 digest；所有实际二进制哈希。
  • 图像/深度/IMU/TF 数据哈希；相机内外参、时间合同、地图参数、场景/路线/足迹/ROI 哈希。
  • 评测器 commit/hash、Python/依赖、完整 CLI、指标协议版本；结果写独立目录，不覆盖历史冻结报告。
  • GPU型号、驱动/CUDA、CPU与线程、内存、存储、功率/频率策略、背景负载与日志设置。

沿用真实的仿真合同，再做外部验证

已有证据 后期批量输入为 GR3 胸部相机下俯 40°，960×600，仿真时间 RGB-D 10 Hz、IMU 200 Hz；RGB rgb8、深度 16UC1 毫米，scale=1000，RGB/深度同 K 且已配准。保留理想完整深度，无噪声和空洞。use_sim_time=true、同步容差1 ms、预热10帧、非零拷贝。[4][8]

数据层用途不能宣称
冻结原始回放算法/参数单变量消融；所有候选消费相同观测重放不是新的物理巡走；理想深度不代表实机深度
Wizard 新户型与新路线测试几何、视角、走廊、白墙与闭环覆盖的外推同户型换材质/路线不算完全独立场景族
TUM RGB-D真实 RGB-D 外部锚定，按序列标定/深度转换TUM PNG scale=5000，不能直接用项目的1000；相机GT需匹配
EuRoC 双目/IMU仅在对应双目或VIO分支存在并适配后验证不是当前RGB-D+仅初始化IMU的直接同赛道比较
目标真实相机曝光、深度空洞、反光/玻璃、同步、标定、真实运动仿真结论不能先行代替实机验证

TUM 的 GT 是彩色相机光心；EuRoC 的数据与真值时空关系、独立曝光和同步限制需按官方说明处理。外部数据各按原协议报告，不能凑成单一平均排行榜。[12][13]

十户型已有协议怎样继承

种子 20261027 从100份冻结生成记录中抽取10户，8户可评测、2户在场景前检即不可通行。case-012、case-003保留为 scene_preflight_unreachable，不替换，不归因成 cuVSLAM 精度失败。总分母10、算法有效n=8并列；不能写成已测100户。[4][6]

建议协议 保留旧10户为历史回归，另建按户型族隔离的 dev/test。图像数据冻结后再比较算法；保持“理想深度”作为主回归轨道，真实噪声支线需要新协议与授权，不擅自改变用户已选条件。

05 / CUSLAM

固定起点与全程对齐必须同时保留

建议主口径沿用十户型固定起点 SE2

十户型 evaluate_single_fixed.py 从第一条精确关联在线 base 位姿建立一次水平刚体变换H，尺度1，复用于全部轨迹、最终地图和墙面评分。建议新补丁主比较继续此口径，输出名 fixed_initial_online_anchor。禁止为地图得高分再做ICP、逐段对齐或自由缩放。[18]

T_A_B：把 B 中的点映射到 A。 T_world_camera = T_world_base × T_base_camera A_start = Pi_SE2(T_GT_base(t0)) × inverse(Pi_SE2(T_EST_base(t0))) Pi_SE2：分别保留 x、y、yaw；scale=1 T_aligned_SE2(t) = A_start × Pi_SE2(T_EST_base(t))

上述 SE2 只比较地面平面位置与 yaw；z/roll/pitch 不在该分数中，必须另报，不能从二维低误差推断完整三维姿态准确。动态胸部相机到 base 的相对关节 TF 必须取图像时刻，不可用单一静态外参替代整个运动序列。

另一已有评测器不是同一地图口径

evaluate_recorded_run.py 同时输出 global_rigid_fit 和每条轨迹各自的 first_pose_anchor；其地图使用 optimized_base_se2的全局刚体拟合，并非在线首锚H。两者都没有map ICP，但不等价。旧报告保留原标签；不能把旧分数重命名成固定起点结果。[1][18]

诊断口径：整条轨迹全局 SE2 与 rig SE3

全程拟合一个固定尺度 SE2 可说明轨迹形状一致性；它利用整条轨迹，通常低于固定起点误差，不能解释成在线机器人知道的全局精度。相机/rig 3D 轨迹另做 SE3 对齐，并明确 GT frame 与轴向。base SE2、rig SE3不混成一列。[1][2]

模式允许的主对齐补充报告
当前 RGB-D 公制链路scale=1；地图/部署口径固定起点SE2全程SE2 ATE、rig SE3诊断、尺度误差（不校正）
真正的公制双目 / VIO 分支通常scale=1的SE3；平面任务可另报SE2不得用Sim3把错误尺度“修好”后当主分数
明确支持的纯单目研究支线可用一个全局Sim3评估形状独立分榜；报告拟合尺度与随时间尺度漂移，不宣称公制定位

evo 的 --align 是 SE3，而不是本项目已有全局 SE2；--align --correct_scale 是 Sim3。因此通用 evo 命令不能替换原评测器后仍沿用旧指标名。[9]

06 / CUSLAM

时间关联与有效分母先于误差公式

  1. 照真实代码做精确关联已有expanded评测器先将timestamp四舍五入到微秒，随后按相等关联；没有最近邻、插值或通用±N毫秒参数。每条轨迹至少3个匹配pose。保留frame ID及未关联数量，不能以1ms图像同步容差代替GT关联规则。
  2. 不要混淆仿真时间和墙钟轨迹对真值使用采样时刻；延迟使用同一主机单调墙钟。不能用“当前墙钟减仿真timestamp”算端到端延迟。
  3. 把缺失留在任务分母里初始化、lost、无输出、超时都影响正确时间/完成率；纯ATE只在有效匹配位姿计算，标为条件误差并同时报有效率。
  4. 断点和重置必须显式每次reset建立segment ID；RPE不跨失跟/重置，ATE不得按segment分别最佳对齐后拼成“完整成功轨迹”。
  5. GT 插值只做透明的离线关联若确需插值，位置线性、旋转SLERP，禁止跨GT断档；记录最大间隔和有效GT时段。原有精确关联主口径不得静默改掉。

正确时间率：每个有效评估时刻同时满足位置≤0.5 m与yaw≤10°才计正确。建议新增GT缺失处理时，分母使用整条输入序列中GT有效的任务时长，初始化/失跟/无输出计不正确；GT缺失单列GT覆盖率与不可评估时长。这是扩展协议，不改变已有expanded全输入帧及其时间支持的历史口径；另报稳态窗口以便诊断。已有expanded评测器同时统计帧正确率与时间正确率，单帧时间支持上限0.15s，较大间隙仍在总时间分母；正确阈值有0.1m/5°、0.25m/5°、0.5m/10°、1m/10°。新增协议若改变加权/GT缺失规则，应升级版本，不能冒充旧实现。yaw差应wrap到[-π,π]后取绝对值。前检失败且没有采集输入的户型，其轨迹时间指标为null，保留在任务完成率分母，不能虚构时间序列。这组阈值来自已有评测口径，不是已获认可的生产安全门限。[1][2]

10帧预热单列输入、初始化和稳态帧数。报告包含完整任务和稳定阶段两组统计，禁止只删掉失败初始化而不留行。最后一帧积分到哪一时刻须由序列结束时刻或冻结规则确定；不得让不同算法的最后有效帧改变分母。GT本身缺失的时段单列“不可评估”，不能由算法失败率替代。

输出可用率实际存在且可解析的位姿输出 / 全部输入；另报满足截止期的及时输出、重复与停滞输出存在不代表准确，也不代表满足实时截止期
完成率与失跟总任务完成率、初始化成功、lost次数/时长、最长缺口、reset、崩溃、超时失败不删除；部分轨迹ATE必须带partial标签
E_i = inverse(T_GT_i) × (A × T_EST_i) ATE_RMSE = sqrt(mean(|| translation(E_i) ||²)) E_ij = inverse(inverse(T_GT_i) × T_GT_j) × (inverse(T_EST_i) × T_EST_j) RPE_trans = ||translation(E_ij)||；RPE_rot = angle(rotation(E_ij))

base主指标先将位姿Π_SE2后代入公式；rig三维诊断才使用完整SE3，二者分别输出。相对误差中的 i,j 必须来自相同预注册配对规则；距离配对以参考轨迹为准，避免估计漂移改变pair选择。固定坐标系变换不会消除局部RPE，但尺度修正会，必须明示。[9][10]

evo的1m RPE输出是该相对区间的平移误差（m）或旋转误差（deg），不自动变成百分比/deg每米；若按实际参考距离归一化需另明示公式。不要加 --correct_scale 给当前RGB-D修分数；--delta_unit s也不是上面核对版本支持的CLI。
